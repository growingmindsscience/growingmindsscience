## 1. Breaks functionality

**No defect was found that breaks the primary (Vercel-served) production site.** The static pages resolve, the API layer is syntactically valid (VERIFIED — `node --check` on all 18 files), the AI path works, and the `nsc` app is green. Items that would elsewhere land here are, on the live path, either degraded-but-not-broken or gated behind a mirror; they are filed under §2–§4 with that framing rather than overstated here.

The one "dead flow" worth naming in this section:

### 1.1 — Subscriber-token Path 3 (bare-email unlock) is effectively unreachable — LOW
- **Where:** `api/verify-subscription.js:157-181` (Path 3 requires `getSession(request)`), which depends on the `gms_session` cookie set only by `api/login.js`.
- **What is wrong:** the only pages that set `gms_session` (`login.html`, `account.html`) are now redirect stubs to the `/nsc` Supabase app (see §4.2). Nothing in the current frontend sets that cookie, so `getSession` always returns `null` and Path 3 always answers `401 "Please sign in…"`.
- **Evidence:** VERIFIED — `grep` for `/api/login`, `data-login-form`, `#login-email` across all `*.html` returns nothing; `login.html:13-21` is a `meta refresh` + `location.replace('/nsc/login')` stub. The AI unlock UI uses Path 1 (`sessionId`) and Path 2 (`token`) plus `/nsc/api/entitlements/me`, none of which need `gms_session`.
- **Impact:** none for users (they never reach Path 3); it is dead surface, not a broken user flow. Real fix belongs in §4.
- **Proposed fix (prose):** decide whether the legacy site-session subscriber unlock is still a supported path. If not, remove Path 3 and the `getSession` import from `verify-subscription.js`, and retire the orphaned auth endpoints (§4.2) together. If it is meant to stay, it needs a page that actually authenticates against `gms_session`, which currently does not exist.

## 2. Security / data risk

No high-severity security issue was found. The items below are real but low-to-moderate, and several are documented trade-offs.

### 2.1 — Orphaned but still-live password-auth + Google OAuth endpoints — MEDIUM (attack surface / confusion)
- **Where:** `api/login.js`, `api/logout.js`, `api/session.js`, `api/auth/google/start.js`, `api/auth/google/callback.js`, `api/_auth.js`.
- **What is wrong:** the entire cookie-session auth subsystem is no longer wired to any page (auth migrated to the Supabase-backed `/nsc` app), yet the endpoints remain deployed and functional. Live-but-unreferenced auth endpoints are unused attack surface: if the `GMS_*`/`GOOGLE_*` env vars are still set in the Vercel project, `POST /api/login` still mints a real `gms_session` cookie that now grants nothing, and the Google OAuth flow still runs. This is confusing for future maintainers and widens the surface for credential-guessing (throttled but present) with no product benefit.
- **Evidence:** VERIFIED — no HTML references `/api/login`/`/api/logout`; `assets/js/main.js:196-290` binds to selectors (`[data-login-form]`, `[data-logout]`, `#login-email`) that exist in no page; `login.html`/`account.html` are redirect stubs (READ).
- **Proposed fix (prose):** if the site has fully standardized on the `/nsc` Supabase identity, delete these endpoints, `_auth.js`, the dead `main.js` auth block, and the now-unused `GMS_LOGIN_*`/`GMS_SESSION_SECRET`/`GOOGLE_*` env vars — after confirming `verify-subscription.js` no longer needs `getSession`. If the legacy login is intentionally kept as a fallback, wire a real login page to it and document why two identity systems coexist.

### 2.2 — Rate limiting is per-instance in-memory, not a global control — LOW (documented)
- **Where:** `api/_ratelimit.js:12-44` and the inline limiter in `api/growing-minds-ai.js:78-123`.
- **What is wrong:** buckets live in a per-edge-instance `Map` and reset on cold start, so login brute-force, subscription-email enumeration (`verify-subscription`), form spam, and free-tier AI abuse are only *blunted per warm instance*, not capped globally. A caller who spreads requests across cold instances or rotates IPs can exceed the nominal limits.
- **Evidence:** READ — the file's own header documents this ("bounds abuse per warm edge instance rather than globally"). The free-tier AI counter is additionally client-resettable (`tools/growing-minds-ai.html:807` writes the count to `localStorage`), but the server-side per-IP/day check is the real gate and the client counter is UX-only by design (READ, `api/growing-minds-ai.js:194-217`).
- **Impact:** the paid-AI gate (access code / subscriber token / nsc entitlement) is *not* affected — only the free allowance and the abuse throttles are soft.
- **Proposed fix (prose):** for the endpoints where abuse actually costs money or leaks signal (`growing-minds-ai`, `verify-subscription`), back the limiter with a shared store (Upstash Redis / Vercel KV) keyed by IP+endpoint, as the header already suggests. Leave the low-value forms (contact/waitlist) on the best-effort limiter.

### 2.3 — Unauthenticated `GET /api/create-checkout-session` creates real Stripe sessions on any hit — LOW
- **Where:** `api/create-checkout-session.js:9-49`; linked from `pricing.html:142` as `<a href="/api/create-checkout-session">`.
- **What is wrong:** the endpoint accepts `GET` and, on every request, calls the Stripe API to create a checkout session, then 303-redirects. Because it is reached via a plain `<a>` link, browser speculative prefetch, link-unfurlers (Slack/email previews), and crawlers that follow the link will each create a spurious Stripe checkout session and consume a Stripe API call. No auth is required (nor needed — checkout creation is public), so this is a cost/noise issue, not an access issue.
- **Evidence:** VERIFIED — `api/create-checkout-session.js:10` allows `GET`; `pricing.html:142` is a GET anchor (VERIFIED via grep).
- **Proposed fix (prose):** make checkout creation `POST`-only and trigger it from a `<form method="post">` submit button (or a small JS handler), so idempotent prefetch/crawl of the pricing page can't mint sessions. Keep the 303 redirect to Stripe on submit.

## 3. Correctness risk

### 3.1 — `netlify/functions/growing-minds-ai.mjs` is a stale, divergent second copy of the AI endpoint — MEDIUM
- **Where:** `netlify/functions/growing-minds-ai.mjs` vs the live `api/growing-minds-ai.js`.
- **What is wrong:** the Netlify copy calls **OpenAI (`gpt-5.5`)** while production on Vercel calls **Anthropic Claude Sonnet**; it is non-streaming and roughly a month behind the Vercel version. Per the project's own memory, two crawlable `*.netlify.app` mirrors of the site are still live. If those mirrors serve this function, a visitor to the mirror gets a *different AI provider, different behavior, and a separate `OPENAI_API_KEY` cost line* from the canonical experience — and any prompt/safety changes made to `api/growing-minds-ai.js` silently do not reach the mirror.
- **Evidence:** VERIFIED — `netlify/functions/growing-minds-ai.mjs:133` = `process.env.OPENAI_MODEL || "gpt-5.5"`; `api/growing-minds-ai.js:259` = `process.env.ANTHROPIC_MODEL || "claude-sonnet-4-6"`. Last-touched: netlify `2026-06-21` vs api `2026-07-19` (VERIFIED — `git log`). The netlify copy imports `redactPII` and applies it once to the whole answer (`:1`, `:173`) but lacks the streaming redactor and the retrieval grounding the Vercel version has.
- **Proposed fix (prose):** decide the mirror's fate. Either (a) fully decommission the Netlify mirrors (the cleanest option — the project already treats `netlify.toml`/`_redirects` as stale and Vercel is canonical), removing `netlify/` and the duplicate function; or (b) if a mirror must stay, regenerate the function from the current `api/growing-minds-ai.js` so provider, streaming, grounding, and privacy hardening match. Do not leave a month-old OpenAI fork of a safety-sensitive endpoint reachable.

### 3.2 — Entitlement reads swallow query errors → transient DB error silently reads as "no access" — LOW
- **Where:** `nsc/lib/entitlements.server.ts:131` and `:141` (also `hasFullAccess`/`hasMembership` reads at `:22, :33, :52`).
- **What is wrong:** each Supabase query destructures only `{ data }` and drops `error`. A transient DB/network failure therefore degrades to *no entitlement* rather than surfacing. For a paywall this fails **closed** (safe direction), but it also masks real outages: a paying member could momentarily appear un-entitled with no logged signal, and there is no way to distinguish "no rows" from "query failed."
- **Evidence:** READ — the reads at `:131-144` bind `{ data: purchase }` / `{ data: ent }` with no `error` handling; the file comment frames this as "tolerant of the table not existing yet."
- **Proposed fix (prose):** capture `error` on each read and log it (server-side) while still degrading closed, so transient failures are observable. Optionally distinguish "table/permission error" (log + alert) from "no rows" (normal) so a real outage isn't invisible.

### 3.3 — `sitemap.xml` advertises a non-canonical URL — LOW (SEO)
- **Where:** `sitemap.xml:16` lists `https://growingmindsscience.com/classes/toddlerhood.html`.
- **What is wrong:** that page's own canonical is the extensionless `https://growingmindsscience.com/classes/toddlerhood` (`classes/toddlerhood.html:19`). A sitemap should list canonical URLs; listing the `.html` variant points crawlers at the non-canonical form of the one class page that *has* a pretty-URL rewrite, muddying which URL Google indexes.
- **Evidence:** VERIFIED — both lines read directly; the other 25 sitemap entries use the clean form.
- **Proposed fix (prose):** change the sitemap entry to `/classes/toddlerhood` to match the canonical. (The other three class pages legitimately keep `.html` because they have no pretty-URL rewrite — leave those.)

### 3.4 — `robots.txt` Sitemap directive is a relative URL — LOW (SEO)
- **Where:** `robots.txt:4` — `Sitemap: /sitemap.xml`.
- **What is wrong:** the sitemap protocol requires the `Sitemap:` directive in robots.txt to be a fully-qualified absolute URL; crawlers may ignore a relative path.
- **Evidence:** READ — the relative value is confirmed in the file; the absolute-URL requirement is well-established sitemap-protocol guidance (BELIEVED, standard spec).
- **Proposed fix (prose):** set it to `Sitemap: https://growingmindsscience.com/sitemap.xml`. This is the same "mirrors must not self-canonicalise" concern the repo already guards for canonicals; the absolute host keeps the directive pointing at production.

### 3.5 — `.html` duplicate URLs are served without a redirect for tools/articles/classes — LOW (SEO, mitigated)
- **Where:** `vercel.json` — only `/pricing.html` and `/milestones.html` have `301` redirects to their clean paths; every other page's `.html` is reachable *and* its clean rewrite is reachable, with no redirect between them. Internal nav compounds this: all 33 standard-nav pages link the AI tool as `/tools/growing-minds-ai.html`, while its canonical is `/tools/growing-minds-ai`.
- **What is wrong:** both URL forms return `200`, creating duplicate-content pairs. It is mitigated because every page's `rel=canonical` points at the clean URL (VERIFIED — `check-canonicals.mjs` passes, 38 pages absolute), so Google should consolidate. But the internal links still send crawlers to the non-canonical form first.
- **Evidence:** VERIFIED — `grep -c permanent vercel.json` = 2; nav links use `.html` (READ, from static map); canonicals are clean (VERIFIED).
- **Proposed fix (prose):** either add `301` redirects from `*.html` to the clean paths for the tools/articles/classes pages (matching what pricing/milestones already do), or switch the internal nav hrefs to the extensionless form so links and canonicals agree. The redirect approach is the more durable fix and also protects the netlify/preview mirrors.

## 4. Hygiene

### 4.1 — `headroom_memory.db` (57 KB SQLite) is committed to the repo — LOW
- **Where:** repo root, tracked in git.
- **What is wrong:** it is the local `headroom` compression tool's SQLite database — a developer-machine artifact with no consumer in any page, build script, or CI step. It should not ship in a static-site repo.
- **Evidence:** VERIFIED — `git ls-files` lists it; `file` reports "SQLite 3.x database"; no build script or page references it.
- **Proposed fix (prose):** `git rm --cached headroom_memory.db` and add it (and any other `*_memory.db`) to `.gitignore`.

### 4.2 — Dead login/logout client code in `assets/js/main.js` — LOW
- **Where:** `assets/js/main.js:196-290` (login submit, logout, `getSession`/`updateAuthNav` wiring).
- **What is wrong:** this block binds to selectors that exist in no current page (auth moved to `/nsc`). It is dead code that still ships to every `main.js` page and misleads readers into thinking the site has a working local login. `updateAuthNav` also injects a "Log in/Account" nav item on `main.js` pages but not on the homepage (which loads `home.js`, not `main.js`), so the nav is inconsistent.
- **Evidence:** VERIFIED — selectors absent from all HTML (grep); `index.html:613-617` loads `home.js` only.
- **Proposed fix (prose):** remove the orphaned auth block from `main.js` as part of the §2.1 cleanup, or, if a unified auth-aware nav is wanted, point it at the `/nsc` session and load it consistently across pages including the homepage.

### 4.3 — CI "skip if not present yet" guards are now dead weight and can mask a broken gate — LOW
- **Where:** `.github/workflows/gates.yml:72-121` — each keyless gate is wrapped in `if [ -f <path> ]; then … else echo "…not present yet…"; fi`.
- **What is wrong:** all six guarded files now exist on `main`, and the workflow's own comment (`:69-70`) says "Remove the guards once they are on main." As written, if any of these files were later renamed or deleted, the step would print "not present yet" and pass **green** instead of failing — silently disabling a safety gate.
- **Evidence:** VERIFIED — all six paths exist and each script runs to exit 0 this session.
- **Proposed fix (prose):** drop the `if [ -f ]` wrappers and invoke the scripts directly, so a missing gate file fails the build loudly.

### 4.4 — `scripts/smoke-tools.mjs` is unrunnable from a clean checkout — LOW (local-only tool)
- **Where:** `scripts/smoke-tools.mjs:4` (`import { chromium } from 'playwright-core'`), `:8` (`EXE = '/opt/pw-browsers/chromium-1194/chrome-linux/chrome'`), `:9` vs header `:3` (port 8267 in code, "8199" in the comment).
- **What is wrong:** it imports `playwright-core`, but the repo root deliberately has no `package.json`/`node_modules`, so the import throws `ERR_MODULE_NOT_FOUND` before anything runs; even past that, the Chrome path is a hardcoded Linux absolute (this repo is macOS) with no `CHROME_BIN` probe (unlike `build-og-cards.mjs:22-34`, which does probe); and the port comment disagrees with the code.
- **Evidence:** VERIFIED — running `node scripts/smoke-tools.mjs` throws `ERR_MODULE_NOT_FOUND: playwright-core`.
- **Proposed fix (prose):** since it is a local-only dev aid (not in CI), either add a `CHROME_BIN`/candidate-path probe and document the `npx playwright` invocation it needs, or remove it if the parent-tools smoke check is no longer used. At minimum fix the port comment.

### 4.5 — Netlify config maintained in parallel and divergent from `vercel.json` — LOW
- **Where:** `_redirects` (92 lines) and `netlify/` vs `vercel.json`.
- **What is wrong:** `_redirects` lacks the `/nsc` proxy and the `/api/stripe-webhook` rewrite that `vercel.json` carries, and uses `200`/`301!` rules Vercel ignores. Two route maps drift apart; the Stripe webhook and Number Path would not route on a Netlify mirror.
- **Evidence:** READ — `_redirects` has no `/nsc` or stripe-webhook entries; `vercel.json:39-42` does.
- **Proposed fix (prose):** decommission the Netlify mirrors (preferred — ties in with §3.1), or if kept, regenerate `_redirects` from `vercel.json` so the two never diverge.

### 4.6 — Agent/tooling scaffolding committed into a production static-site repo — LOW (noise)
- **Where:** `.agents/`, `.impeccable/`, `.serena/`, `skills-lock.json` (tracked).
- **What is wrong:** none of these are referenced by any build script, page, or CI; they are local agent-tooling scaffolding adding noise to a repo whose deploy is "serve the files as-is."
- **Evidence:** VERIFIED — not referenced by any gate or script (grep).

### 4.7 — `milestones.html` uses a bespoke nav diverging from the other 33 pages — LOW (consistency)
